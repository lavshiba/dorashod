# Финансы

Production-ready Telegram-бот для учёта доходов и расходов прямо в Telegram. Проект рассчитан на автономную работу 24/7 без включённого компьютера владельца: весь runtime живёт в Cloudflare Workers, данные хранятся в Cloudflare D1, входящие обновления Telegram принимаются через webhook, а периодические проверки и напоминания запускаются через Cloudflare Cron Triggers.

Тексты интерфейса сейчас дополнительно заморожены внешним пакетом:

- `/home/abihsgelo/.var/app/org.telegram.desktop/data/TelegramDesktop/tdata/temp_data/codex_ui_texts_package/frozen_ui_texts_for_codex.txt`

Если тексты в коде или документации расходятся с этим файлом, приоритет у него.

Под новый frozen-файл уже приведены onboarding, главная, `новая запись`, `черновик`, `новые записи`, `операции`, карточка записи и `изменить запись`.

Форматирование экранного текста теперь больше не вставляет самовольные пустые строки между соседними строками: в проде сохраняются именно те переносы, которые заданы в frozen-тексте.

Последний экран бота теперь переиспользуется не только внутри callback, но и между отдельными update через сохранённый `screenMessageId` в `ui_sessions`, чтобы в Cloudflare-окружении было меньше лишних сообщений.

Команда `/start` теперь обрабатывается как reset экрана: бот старается удалить саму команду, удалить прошлый экран и создать один новый стартовый экран вместо накопления нескольких главных.

## Текущий статус

Сейчас в проекте уже есть:

- GitHub-репозиторий: `https://github.com/lavshiba/dorashod`
- production Worker: `https://finance-bot.shiaboi.workers.dev`
- health endpoint: `https://finance-bot.shiaboi.workers.dev/health`
- webhook Telegram: `https://finance-bot.shiaboi.workers.dev/webhook/telegram/<secret>`
- D1 database `finance-bot-db`
- активные cron triggers `*/10 * * * *` и `0 4 * * *`
- GitHub CI и GitHub deploy workflow

Подтверждено автоматически:

- локальные `lint`, `build`, `test`, `check`
- GitHub Actions `ci`
- remote миграции D1
- прод-ответ `health`
- прод-ответ `diagnostics`
- регистрация cron schedules
- установка webhook

Пока не доведены до полного `definition of done`:

- полный охват всех продуктовых сценариев из ТЗ
- полный import/export flow
- массовые действия уже умеют базовый перенос, удаление и снятие подкатегории, но ещё не покрывают все крайние случаи ТЗ
- часть категорийного, подкатегорийного и карточечного flow ещё не доведена до конца
- часть крайних случаев импорта и custom period parsing ещё не доведены до полного соответствия ТЗ
- живой ручной чек реального ответа бота в вашем Telegram-чате

## Что умеет бот

- Пошагово и текстом добавлять доходы и расходы.
- Продолжать onboarding с того же шага после прерывания.
- Сохранять неполную запись как черновик.
- Складывать пачки записей и проблемные строки импорта в очередь `новые записи`.
- Показывать `операции`, `поиск`, `отчёт`, `категории`, `настройки`, `данные`.
- Показывать breakdown отчётов по расходам и доходам, карточки категорий и подкатегорий и списки `все записи` внутри отчёта.
- Поддерживать режим выбора нескольких записей в `операции`, `поиск` и списках отчёта.
- Выполнять базовые массовые действия: `перенести`, `удалить`, `снять подкатегорию`.
- В массовом переносе спрашивать подкатегорию только если у целевой категории она реально есть.
- В `выбрать все` на текущей странице уметь не только добавить выбор, но и снять его с этой страницы.
- Показывать стрелки перехода между записями внутри текущего списка и базовые карточки подкатегорий в разделе `категории`.
- Принимать файл в разделе `данные`, показывать preview полной копии и загружать записи из файла через `объединить` и `добавить всё`.
- Открывать `исправить n` по проблемным строкам импорта и разбирать их по одной.
- После загрузки файла с записями возвращать единый preview-экран с `объединить`, `добавить всё` и `исправить n`, а не разрывать сценарий на отдельные тупиковые ветки.
- В `исправить` сохранять дату и время из исправленной строки, если они уже читаются, а не терять их молча.
- В `исправить` по кнопке `[сохранить]` переносить строку в preview импорта, а не добавлять её в данные раньше `объединить` или `добавить всё`.
- Лучше разбирать чужие CSV: `;`, tab, русские и английские заголовки, даты с временем, запятую как десятичный разделитель и знак суммы для вывода типа.
- Понимать `свой период` заметно лучше: день, месяц, год, относительные периоды и часть диапазонов, с подтверждением для двусмысленных вариантов.
- После двусмысленного `свой период` принимать и новый период сообщением, не выбрасывая пользователя из сценария отчёта.
- Разбирать более естественные диапазоны `свой период`: `с 01.03.2026 по 10.03.2026`, `01.03 - 05.03`, `2026-03 - 2026-05`, `2024 - 2025`, `1 марта - 10 марта`.
- Показывать скрытые подкатегории внутри категории и честно запрещать удаление непустых категорий и подкатегорий.
- Держать длинные списки подкатегорий внутри карточки категории и карточки категории в отчёте на отдельной внутренней пагинации, а не раздувать один экран.
- В `изменить` спрашивать подтверждение перед уходом без сохранения, если есть несохранённые изменения.
- Давать `изменить время` из карточки записи, если время было поставлено автоматически.
- Редактировать дату и время записи внутри `изменить`.
- После сохранения и удаления записи честно возвращаться в тот список, из которого запись была открыта.
- После массовых действий честно возвращаться в `операции`, `поиск`, `отчёт` или фильтрованный список категории.
- Поддерживать `выбрать несколько` в списках записей категории и подкатегории.
- Показывать рабочую пагинацию в `операции`, `поиск`, списках отчёта, категориях, скрытых списках и фильтрованных списках записей.
- Открывать рабочие экраны `быстрый доступ` и `сортировка` вместо пустых кнопок.
- Поддерживать `свои` слоты быстрого доступа для категорий и подкатегорий с перестановкой и очисткой.
- Давать листать выбор категории и подкатегории в `быстрый доступ`, а не обрывать его первой страницей.
- Настраивать быстрый доступ для подкатегорий внутри выбранной категории, а не через скрытую привязку к последней открытой категории.
- Для подкатегорий поддерживать не только общий режим сортировки, но и локальный режим внутри конкретной категории, со `сбросить к общему`.
- Показывать быстрый доступ в пошаговом добавлении записи, если он включён.
- Поддерживать `изменить` для категорий и подкатегорий с проверкой дублей и сценарием `вернуть` для скрытых сущностей.
- Применять настройку времени через город и через геопозицию к вычислению `сегодня`, `вчера`, быстрых периодов и главной.
- Применять настройки сортировки к спискам категорий и подкатегорий.
- Выполнять `перенести все записи` у категории и подкатегории с очисткой неподходящих подкатегорий при переносе категории.
- При `перенести все записи` у категории больше не переносить записи в скрытые подкатегории целевой категории и честно показывать, сколько записей осталось без подкатегории.
- Скрытые категории и скрытые подкатегории теперь лучше держат свой контекст: карточки, `все записи`, `изменить`, `удалить` и возвраты больше не выбрасывают пользователя в обычные списки раньше времени.
- При кнопочной навигации стараться обновлять один и тот же экран через `editMessageText`, а не плодить новое сообщение на каждый переход.
- Делать экранный текст более читаемым за счёт абзацев и воздуха между строками, не меняя сами согласованные формулировки из ТЗ.
- После действий вроде импорта, переноса всех записей и исправления проблемных строк чаще показывать итог прямо в целевом экране, а не отдельным подтверждением плюс ещё одним экраном.
- После сохранения записи из `новые записи`, после `изменить` и после `сбросить настройки` показывать короткий итог прямо в том экране, где пользователь остаётся дальше.
- Этот же подход теперь применяется и в `настройки`: валюта, время, подкатегории, быстрый доступ и сортировка показывают короткий итог прямо в текущем экране после изменения.
- Теперь это же протянуто и на `категории` / `подкатегории`: создание, скрыть, вернуть, удалить и переименование чаще завершаются тем же экраном с коротким итогом сверху.
- Делать резервную копию для этого бота и обмен файлами записей с другими приложениями.
- Работать с webhook, cron, health check, миграциями и диагностикой в проде.

## Деплой

Основной поток:

1. `npm install`
2. `npm run check`
3. `wrangler login`
4. `wrangler d1 create finance-bot-db`
5. Обновить `database_id` в [wrangler.jsonc](/home/abihsgelo/Документы/dorashod/wrangler.jsonc)
6. Задать секреты через `wrangler secret put`
7. `npm run d1:migrate:remote`
8. `npm run deploy`
9. Поставить webhook и прогнать post-deploy checks

Подробная операционная инструкция находится в [docs/operations.md](/home/abihsgelo/Документы/dorashod/docs/operations.md).

## Ограничения free-плана

- Нужно экономить D1-запросы и cron-выполнения.
- Нельзя держать тяжёлые постоянные фоновые циклы.
- Нельзя делать бессмысленные пинги для “поддержания жизни”.
- Важно аккуратно проектировать SQL, индексы и пагинацию.

Проект учитывает это так:

- минимизирует количество запросов на обычные пользовательские действия
- хранит компактные UI-состояния
- использует paginated list views
- выносит периодические задачи в редкие cron-проверки
- избегает ORM-магии и лишних запросов

Компромиссы и риски описаны в [docs/architecture.md](/home/abihsgelo/Документы/dorashod/docs/architecture.md) и [docs/operations.md](/home/abihsgelo/Документы/dorashod/docs/operations.md).
