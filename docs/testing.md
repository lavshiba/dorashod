# Testing

## Обязательные локальные проверки

- `npm run lint`
- `npm run build`
- `npm run test`
- `npm run d1:migrate:local`

## Стратегия тестирования

- Unit tests: нормализация, парсинг записей, словарь, report period parsing, duplicate detection.
- Integration tests: сценарии экрана и сервисов поверх in-memory fixtures.
- Smoke tests: health, webhook, базовые use cases.
- Post-deploy checks: реальные HTTP и Telegram checks после `wrangler deploy`.

## Текущий фактический охват

Автоматически покрыты сейчас:

- frozen словарь кнопок и onboarding progress
- базовый парсинг одиночной записи и пачки записей
- CSV-импорт: `;`, русские заголовки, вывод типа по знаку суммы, нечитаемая дата и отсутствие времени
- health endpoint
- post-deploy smoke skeleton
- production health
- production diagnostics
- production D1 migration
- production webhook installation
- production cron registration

Реализовано и проверено локальным `npm run check`, но ещё не закрыто отдельными сценарными тестами:

- время через город и геопозицию влияет на вычисление пользовательской даты
- сортировка категорий и подкатегорий влияет на реальные списки
- `перенести все записи` у категории и подкатегории больше не является пустым сценарием
- `быстрый доступ` со слотами влияет на пошаговое добавление записи
- `изменить время` и редактирование даты/времени влияют на карточку и возврат в исходный список
- массовые действия и возвраты после удаления держат исходный список точнее, чем раньше
- пагинация теперь реально работает в длинных списках `операции`, `поиск`, `отчёт`, `категории`, `скрытые` и фильтрованных списках записей
- выбор категории и подкатегории в `быстрый доступ` тоже листается по страницам
- настройка `быстрый доступ` для подкатегорий теперь идёт внутри выбранной категории, а не через неявную последнюю категорию из сессии
- импорт записей теперь после загрузки файла держит единый preview-экран с `объединить`, `добавить всё` и `исправить n`
- массовый перенос теперь спрашивает подкатегорию только если у целевой категории она действительно есть
- `выбрать все` на текущей странице теперь умеет и снимать выбор с этой страницы, если она уже выбрана целиком

Полная матрица ниже остаётся definition of done и ещё требует дальнейшего покрытия.

## Post-deploy checks

После деплоя проверить:

- worker опубликован
- webhook поставлен и отвечает
- d1 доступна
- базовые команды бота работают
- добавление записи в проде работает
- чтение записи в проде работает
- поиск в проде работает
- отчёт в проде работает
- cron jobs реально зарегистрированы
- `health` отвечает

Если какой-то пункт не удалось проверить автоматически, нужен минимальный ручной чек с честной фиксацией статуса.

Текущий минимальный ручной чек:

- открыть `@dorashodbot`
- отправить `/start`
- убедиться, что приходит onboarding / стартовый экран уже из production webhook
