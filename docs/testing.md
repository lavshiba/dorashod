# Testing

## Обязательные локальные проверки

- `npm run lint`
- `npm run build`
- `npm run test`
- `npm run d1:migrate:local`

## Стратегия тестирования

- Unit tests: нормализация, парсинг записей, словарь, report period parsing, duplicate detection.
- Integration tests: сценарии экрана и сервисов поверх in-memory fixtures.
- Smoke tests: health, webhook, базовые use cases.
- Post-deploy checks: реальные HTTP и Telegram checks после `wrangler deploy`.

## Текущий фактический охват

Автоматически покрыты сейчас:

- frozen тексты из repo и внешний frozen-файл пользовательских текстов сверяются вручную как source of truth
- frozen словарь кнопок и onboarding progress
- под внешний frozen-файл уже вручную переведены onboarding, главная, `новая запись`, `черновик`, `новые записи`, `операции`, карточка записи, `изменить запись`, а также заметные части `настройки` и `данные`
- helper форматирования экранов теперь сохраняет ручные переносы строк из frozen-текстов и не добавляет воздух между каждой строкой
- базовый парсинг одиночной записи и пачки записей
- CSV-импорт: `;`, русские заголовки, вывод типа по знаку суммы, нечитаемая дата и отсутствие времени
- импорт записей теперь проходит через более честный dry-run перед `объединить` и `добавить всё`
- health endpoint
- post-deploy smoke skeleton
- production health
- production diagnostics
- production D1 migration
- production webhook installation
- production cron registration

Реализовано и проверено локальным `npm run check`, но ещё не закрыто отдельными сценарными тестами:

- время через город и геопозицию влияет на вычисление пользовательской даты
- сортировка категорий и подкатегорий влияет на реальные списки
- `перенести все записи` у категории и подкатегории больше не является пустым сценарием
- `быстрый доступ` со слотами влияет на пошаговое добавление записи
- `быстрый доступ` и `сортировка` больше не застревают в режимах без обратного пути к `автоматически` и `по количеству операций`
- prompt-экраны поиска, своего периода, категорий и подкатегорий стали ближе к frozen-подаче и меньше звучат как технические заглушки
- скрытые списки и часть пустых состояний тоже подтянуты ближе к frozen-подаче
- конфликт поиска с новой записью, пачкой записей и неполный текстовый ввод тоже стали ближе к frozen-подаче
- add/edit prompts и сообщения об ошибках разбора тоже стали спокойнее и менее техническими
- массовые действия и выход из выбора тоже стали ближе к frozen-подаче
- края категорий и переносов тоже стали ближе к frozen-подаче и менее техничными
- `изменить время` и редактирование даты/времени влияют на карточку и возврат в исходный список
- массовые действия и возвраты после удаления держат исходный список точнее, чем раньше
- пагинация теперь реально работает в длинных списках `операции`, `поиск`, `отчёт`, `категории`, `скрытые` и фильтрованных списках записей
- выбор категории и подкатегории в `быстрый доступ` тоже листается по страницам
- настройка `быстрый доступ` для подкатегорий теперь идёт внутри выбранной категории, а не через неявную последнюю категорию из сессии
- импорт записей теперь после загрузки файла держит единый preview-экран с `объединить`, `добавить всё` и `исправить n`
- массовый перенос теперь спрашивает подкатегорию только если у целевой категории она действительно есть
- `выбрать все` на текущей странице теперь умеет и снимать выбор с этой страницы, если она уже выбрана целиком
- длинные списки подкатегорий в карточке категории и в карточке категории отчёта теперь листаются внутренней пагинацией
- `исправить` для проблемной строки теперь сохраняет найденные дату и время из исправленного текста, если они читаются
- `исправить` по `[сохранить]` теперь staging-only: строка уходит в preview импорта и не попадает в базу до общего решения `объединить` или `добавить всё`
- после двусмысленного `свой период` новый период сообщением остаётся в том же сценарии отчёта
- `свой период` теперь покрыт unit-тестами и понимает больше естественных диапазонов, включая короткие даты, годы, месяцы и даты с названием месяца
- `перенести все записи` у категории теперь не подбирает скрытые подкатегории целевой категории и отдельно считает, сколько записей осталось без подкатегории
- скрытые категории и скрытые подкатегории теперь лучше сохраняют контекст через карточки, списки `все записи`, `изменить`, `удалить` и возвраты
- сортировка подкатегорий теперь поддерживает и общий режим, и локальный режим для одной категории, включая `сбросить к общему`
- callback-навигация теперь по возможности обновляет текущий экран, а не создаёт новый
- форматирование экранного текста теперь добавляет воздух между блоками, не меняя frozen тексты
- часть действий, которые раньше давали `подтверждение + ещё один экран`, теперь схлопнута в один итоговый экран со статусом сверху
- этот же подход теперь протянут и на часть карточечных итогов: `новые записи`, `изменить`, `сбросить настройки`
- в `настройки` изменения валюты, времени, подкатегорий, быстрого доступа и сортировки теперь тоже возвращают тот же экран с коротким итогом сверху
- `категории` и `подкатегории` теперь тоже чаще завершают действие тем же экраном с коротким итогом сверху, вместо молчаливого возврата
- shell-экраны `настройки`, `данные`, `быстрый доступ`, `сортировка`, время и часть категорийных дублей/подтверждений теперь тоже приведены к общему виду с шапкой `финансы`
- смешанный латинско-кириллический хвост в пустом экране `операции` убран
- после обработанного текстового ввода, геопозиции и загрузки файла бот теперь пытается удалить само пользовательское сообщение
- callback-lock теперь протухает по времени и больше не должен навсегда блокировать повторное нажатие той же кнопки на том же экране
- add-flow теперь имеет рабочие `все категории`, `все подкатегории`, создание категории и подкатегории прямо из сценария добавления и отдельный шаг `назад` вместо битых callback’ов
- если Telegram не даёт отредактировать старый экран, бот теперь старается удалить его перед отправкой нового, чтобы меньше плодить дубли экранов
- update’ы одного пользователя теперь последовательно сериализуются через D1 lock, чтобы быстрые серии сообщений и нажатий меньше ломали живую сессию
- удаление входящих сообщений и старых экранов теперь идёт через несколько коротких retry, чтобы уменьшить число висящих сообщений в живом Telegram
- главный экран теперь сам сбрасывает UI-сеанс в `idle`, чтобы следующий ввод не продолжал старый сценарий под видом уже открытой главной
- `новые записи` теперь держат собственный add-flow-контекст: `изменить` и последующее `сохранить` возвращают в очередь, а не выбрасывают в обычный сценарий добавления
- если внутри пошагового добавления приходит полноценная новая запись или пачка записей, бот теперь не должен ошибочно трактовать их как следующее поле текущего черновика
- callback-data теперь кодируется компактнее и имеет unit-тесты, чтобы длинные payload’ы реже упирались в лимит Telegram
- ожидание user-level lock увеличено: при плотных сериях update’ов бот теперь дольше ждёт очереди и должен реже терять сообщения или нажатия
- после ужатия callback-data `поиск` теперь должен восстанавливать текущий запрос из session-контекста и не терять выдачу при переходах в карточку и обратно
- ещё один слой служебных экранов переведён в нормальный shell с шапкой `финансы`: неполный разбор записи, preview полной копии, `действия с записями`, prompt `изменить запись`
- верхние экраны `поиск`, `отчёт`, `настройки` и `данные` ещё точнее подтянуты к frozen-подаче, а `быстрый доступ -> подкатегории` снова работает как отдельный выбор категории, а не как сбившийся режим категорий
- списки записей категории и подкатегории теперь тоже ближе к frozen-подаче: записи показываются блочнее, а номерные кнопки снова раскладываются по нескольким рядам
- `исправить импорт` теперь тоже ближе к frozen-подаче: распознанные дата и время показываются прямо в разборе, а кнопка первого недостающего шага называется по самому полю, а не общим `изменить`
- быстрые периоды в `поиск` снова показываются как отдельные экраны `записи за ...`, а карточки записей перестали светить сырыми датами из базы и используют человекочитаемый формат
- `отчёт` тоже ближе к frozen-подаче: пустой отчёт короче, breakdown-экраны снова показывают `всего`, а подкатегории в карточке категории отображаются блочнее
- экран импорта со строками ошибок теперь тоже ближе к frozen-логике: это понятный шаг `добавить n / исправить n`, а не внутренний выбор между нашими техническими режимами
- `перенести все записи` у категории и подкатегории теперь уже ближе к frozen-сценарию: выбор цели стал кнопочным, а у категории появилось отдельное предупреждение перед очисткой неподходящих подкатегорий
- списки `все записи` внутри `отчёт` теперь тоже ближе к frozen-ТЗ: `записи категории` и `записи подкатегории` показывают правильные заголовки с сущностью и периодом, а подкатегория не дублирует лишний контекст в каждой строке
- карточки скрытых категорий и подкатегорий тоже ближе к frozen-порядку действий: `вернуть` теперь стоит перед `изменить`, чтобы порядок кнопок совпадал с экранной логикой из ТЗ

## Post-deploy checks

После деплоя проверить:

- worker опубликован
- webhook поставлен и отвечает
- d1 доступна
- базовые команды бота работают
- добавление записи в проде работает
- чтение записи в проде работает
- поиск в проде работает
- отчёт в проде работает
- cron jobs реально зарегистрированы
- `health` отвечает

Если какой-то пункт не удалось проверить автоматически, нужен минимальный ручной чек с честной фиксацией статуса.

Текущий минимальный ручной чек:

- открыть `@dorashodbot`
- отправить `/start`
- убедиться, что приходит onboarding / стартовый экран уже из production webhook
- пройти быстрый сценарий `операции -> выбрать несколько -> удалить / перенести / снять подкатегорию` и убедиться, что статус остаётся внутри того же экрана списка
- открыть пустую и непустую категорию, проверить подтверждения удаления и возвраты в тот же раздел
- зайти в `поиск`, `свой период`, `данные -> исправить импорт`, `настройки -> быстрый доступ/сортировка` и проверить, что prompts показываются как полноценные экраны с шапкой `финансы`
- в `новая запись` и `изменить запись` вручную проверить ошибки суммы, типа, даты и времени: бот должен оставаться в спокойном экранном стиле, а не отвечать голой служебной репликой
- в `категории` и `подкатегории` вручную проверить `новая`, `изменить`, `вернуть` и дубли скрытых сущностей: экраны должны оставаться в frozen-подаче без лишних промежуточных статусов
- в карточках категории и подкатегории вручную проверить порядок кнопок: сначала `изменить`, потом `скрыть/вернуть`, потом `удалить`, затем `все записи`
- в `выбрать несколько -> перенести` вручную проверить новый кнопочный сценарий: сначала выбор `категорию` / `подкатегорию`, затем выбор цели без сырого стартового prompt
- в `данные` вручную проверить все входы в `загрузить из файла`: из раздела данных, из onboarding и при случайной отправке документа бот должен показывать один и тот же нормальный экран ожидания файла
- в пустых экранах `скрытые`, `быстрый доступ`, `сортировка подкатегорий` проверить, что формулировки идут в нормальном frozen-порядке слов, а не как технические заготовки
- в `быстрый доступ -> подкатегории` вручную проверить пустой chooser: он должен спокойно возвращать назад, а не звать добавлять что-то в обход сценария
- в `данные -> в другие приложения` вручную проверить цепочку `preview -> план -> подтверждение -> назад`: кнопка `[назад]` должна возвращать на предыдущий экран импорта, а не в корневой раздел данных
- в `данные -> исправить импорт` вручную проверить `изменить -> отмена`: возврат должен оставлять на той же проблемной строке, а не переносить в начало очереди
- в `данные -> в другие приложения` вручную проверить крайний случай `0 готовых записей + есть ошибки`: бот не должен показывать кнопку `добавить 0`, только дальнейшую работу с ошибочными строками
- в `данные -> в другие приложения -> объединить` вручную проверить случай, где все записи уже есть: бот не должен давать ложный шаг `добавить 0`
- в `настройки -> быстрый доступ` вручную проверить, что слоты идут отдельными кнопками по одному, а не одной длинной строкой
- в `настройки -> быстрый доступ -> подкатегории -> категория без подкатегорий` вручную проверить, что есть нормальный следующий шаг `[+ подкатегория]`
- в `настройки -> сортировка -> подкатегории -> категория без локального override` вручную проверить, что кнопка `[сбросить к общему]` не показывается лишний раз
- в живом Telegram-чеке вручную проверить `отмена`, `на главную`, сохранение записи текстом и быстрые переходы по кнопкам: бот должен заметно реже плодить второй экран поверх старого
- в `данные -> для этого бота -> загрузить из файла` вручную проверить, что после файла открывается тот же normal preview-экран, что и в основной ветке полной копии, а не отдельная ручная реплика
- в `данные -> в другие приложения -> добавить всё` вручную проверить случай `0 добавлений`: бот не должен вести в ложный шаг `добавить 0`
- в `данные` вручную проверить входы `загрузить из файла`, чтение файла и `исправить импорт`: после этих шагов бот должен чаще обновлять текущий экран, а не присылать рядом новый
- в живом Telegram-чеке вручную пройти onboarding, `доход/расход`, `поиск`, `отчёт`, `категории`, `настройки`, `новые записи`, `изменить запись` и проверить, что между шагами бот заметно реже теряет один экран
